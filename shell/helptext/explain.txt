explain [options] - Generate AI explanation for the current position

  Uses AI (Gemini, OpenAI, or DeepSeek) to provide detailed explanations of the best plays
  in the current position. The AI analyzes simulation results and provides
  insights about tile leaves, strategic considerations, and play selection.

  Requirements:
  - A game must be loaded or created
  - At least 9 unseen tiles (not available in endgame positions)
  - AI provider configured (see `help setconfig` for setup)

  Options:
    -plies <n>      Number of simulation plies (default: 5)
    -opprack <rack> Set opponent's rack for simulation
    -stop <n>       Stop simulation at n% confidence level (default: 99)
    -vs <play>      Explain why the best play beats this one, instead of just
                    why it is good. Use "off" to turn the comparison off.
    -infer          Read the opponent's rack from their last play, and
                    simulate both with and without that read
    -infer-time <n> Seconds to spend inferring (default 20); implies -infer
    -show-prompt    Also print the full prompt that was sent to the model
    -show-previous-prompt
                    Print the last prompt and response instead of explaining
                    anything. Nothing is simulated and no API call is made.

  Examples
      explain
      explain -plies 3 -stop 95
      explain -opprack AEINRST
      explain -vs "12J EQU(ID)"
      explain -vs off
      explain -show-prompt
      explain -show-previous-prompt
      explain -plies 4 -stop 95 -opprack TESTING

  Comparing against your own play:

  When you are stepping through a loaded game, `explain` compares the best play
  against the play you actually made on that turn, and answers "why is this
  better than what I played?". It finds that play in the game history, so there
  is nothing to pass. Use `-vs off` for a plain explanation, or `-vs <play>` to
  ask about some other play instead.

  The play is simulated even if it wouldn't otherwise have made the cut, so a
  bad move still gets a real answer. Write it the way the tables do, either
  `12J EQU(ID)` or `12J EQU..`, and quote it if it contains spaces.

  If the play you made is the best one, `explain` says so and compares it
  against the runner-up instead.

  Reading the opponent's rack:

  `explain -infer` runs a 20-second inference on the opponent's last play
  first, then simulates twice: once sampling their rack from what the read
  concluded, and once ignoring it. The explanation is built on the first, and
  the second is what lets it say what the read actually changed.

  Nothing about the read reaches the explanation unless it earns its place. It
  has to say something - some tile has to be meaningfully likelier or less
  likely than chance, measured in tiles of a rack rather than as a ratio - and
  it has to have changed the analysis, either by recommending a different play
  or by moving the recommended play's win% by enough to matter. A read that is
  interesting but changes nothing is left out, as is one in a position that is
  already won or lost.

  Expect this to take a while: a 20-second inference plus two full simulations.
  If there is nothing to infer from, or the inference concludes nothing, you
  still get an ordinary explanation.

  Seeing the prompt:

  The prompt is assembled from computed facts and whichever strategy concepts
  the position calls for, so reading the exact text that produced an
  explanation is the practical way to debug a bad one. `-show-prompt` prints it
  alongside the answer; `-show-previous-prompt` prints the last one and its
  response, which still works after you have moved on to another position.

  The command will:
  1. Generate top moves if not already done
  2. Run Monte Carlo simulation to evaluate positions (stops at 99% confidence)
  3. Send results to AI for detailed analysis
  4. Return comprehensive explanation with strategic insights

  Configuration:
  Use `setconfig` to configure AI settings:
  - setconfig genai-provider gemini     (or openai, or deepseek)
  - setconfig gemini-api-key <key>      (or openai-api-key, or deepseek-api-key)
  - setconfig gemini-model <model>      (or openai-model, or deepseek-model)

  Local LLM (LM Studio, Ollama, vLLM, etc.):
  Any OpenAI-compatible local server works by pointing the openai provider at it:
  - setconfig genai-provider openai
  - setconfig openai-base-url http://127.0.0.1:1234/v1   (LM Studio default port)
  - setconfig openai-model <model-id>   (copy the model ID shown in LM Studio)
  No API key is required for local servers.

  Note: tool-calling support depends on the local model. Models with function-
  calling capability (e.g. Llama 3.1+, Mistral, Gemma 3) work best.

  See `help setconfig` for more configuration options.
