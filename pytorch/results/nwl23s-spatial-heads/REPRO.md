# nwl23s: transformer value net with per-square placement heads

Result (2026-09-27): a value net trained with four auxiliary per-square
"placement" heads beats HastyBot at 57% in paired play, against 53% for the
same net, same data, same recipe without them. See RESULTS.md for the final
match statistics (appended by `pytorch/finalize-nwl23s.sh`).

## What the model is

`macondo-nn-tf-nwl23s` v1: the Macondo transformer value net
(`pytorch/transformer_model.py`; d=192, 8 layers, 6 heads, ff x4, 3,665,355
parameters; 254 tokens: CLS + 225 squares + 27 tile types + 1 game token) with
the WDL head as the primary objective. The served ONNX exports only
`value` = P(win) - P(loss) from the WDL softmax and `spread`. The four
spatial heads (`heads_spatial`, one Linear(192, 4) shared by the 225 square
tokens) exist only in the checkpoint and only shaped the trunk during
training. Inputs at play time are unchanged from every earlier model
(85 planes + 72 scalars).

## Data

54M NWL23 games, `RANDOM_BOT_WITH_TEMPERATURE` (top 50 by equity, softmax
T=1 point while bag > 60, greedy after) vs `HASTY_BOT`, quick 2-ply endgame
search for both bots when |spread| <= 60 (tiny window, 250 ms cap). Three
halves, generated 2026-09-24/25 with `pytorch/run-fresh.sh` /
`run-nwl23-topup.sh`; configs in `logs/nwl23{a,b,c}.config.json`; turn logs
kept at `~/data/nwl23{a,b,c}.txt.gz` (md5 of c: 16e5e6aa1cffa6ad0248aada269e63b3).

Scan (2026-09-26 14:59-16:39, `run-spatial.sh`):

    zcat nwl23{a,b,c}.txt.gz | bin/mlproducer -labeler result -per-game -endgame-plies 2 \
      | python training.py --cache-only --cache nwl23s-frames.bin

One position per game, turn drawn uniformly from 1..30, empty-bag draws
skipped; labels: the mover's true game result (WDL), spread to the end,
opponent's next-move bingo and score, and the four placement planes (the
squares of the opponent's next move, of the mover's next move, and each
kept only when that player won). 36,400,365 rows, 2,812 bytes each
(102 GB; not archived, rebuildable from the logs in ~1 h 40 min).
The producer replays half of all games transposed (`shouldTranspose`).

## Training

2026-09-26 20:35 to 2026-09-27 10:31, `pytorch/train-fresh.sh` under
`run-spatial.sh` with `SCAN=0 TRANSPOSE=0`:

    PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
    python training.py --arch transformer --ckpt best-tf-nwl23s.pt --csv loss_tf_nwl23s.csv \
      --primary wdl --w-wdl 1 --w-value 0 --aux-share 0.15 --spatial-share 0.1 \
      --transpose-prob 0 --batch-size 128 --accum 16 --epochs 3 \
      --from-cache nwl23s-frames.bin --val-size 150000 --total-steps 53000 --snapshot-every 10000

AdamW lr 3e-4, 2,000-step warmup then cosine to zero at 53,000 steps
(effective batch 2,048, 3 epochs over 36.25M rows), bf16 autocast, grad
clip 1.0, weight decay 1e-4. Auxiliary weights re-balanced every 500 steps
so each aux head's trunk gradient is 0.15x the WDL head's (0.10x for the
spatial heads); the spatial weights ended near 1.0 (see
`logs/loss_tf_nwl23s.csv`, columns `w_*`). Best validation WDL cross-entropy
0.4993 at step 51,000 (the served checkpoint) vs 0.5004 for the run without
spatial heads. Peak GPU memory 3.2 GiB, 2,164 pos/s, 13.9 h on an RTX 3070 Ti.

## Match

    MACONDO_TRITON_USE_TRITON=true MACONDO_TRITON_URL=localhost:8101 \
    MACONDO_TRITON_MODEL_NAME=macondo-nn-tf-nwl23s MACONDO_TRITON_MODEL_VERSION=1 \
    bin/shell autoplay -botcode1 FAST_ML_BOT -botcode2 HASTY_BOT -lexicon NWL23 \
      -numgames 100000 -gamepairs true -threads 12 -block true -experimentid tf-nwl23s-v-hasty-pairs

Master seed (generated by the run, replays it with `-seed`): 7744621849246281743.
100k pairs (200k games), each seed played twice with the seats swapped,
same tile order; FastMlBot ranks the top 50 plays by static equity with the
net's `value` and plays the endgame with HastyBot's static evaluation (no
solver on either side). Statistics: `pytorch/pairs-stats.py` (per-pair win
share with its standard error). Comparison runs, same harness and lexicon:

## Checks made before believing it

- The match process's environment names `macondo-nn-tf-nwl23s` v1; Triton
  lists it READY; the ONNX md5 matches the archived file; the parity check
  passed.
- HastyBot's side is unchanged: the shell binary had been rebuilt with an
  unrelated autoplay change (sampled openings, `9bfd80f3`), so 600 seeded
  HastyBot-vs-HastyBot games were played under the old (`0986c24f`) and new
  binaries: 13,650 turns, byte-identical.
- First-mover win rate 0.556, the same as in every earlier match, so the
  engine and pairing behaved as before.
- Per-bot statistics against the nwl23 match: HastyBot's mean score fell
  434.2 -> 426.7 and its bingos per game 2.018 -> 1.968, FastMlBot's score
  432.8 -> 428.1 with bingos unchanged, spread per game -1.4 -> +1.4. Lower
  scores on both sides with the opponent's bingo rate down is what a more
  defensive, board-aware player produces; it is not what a scoring bug
  produces.
- The auxiliary targets cannot leak into play: they are used only in the
  loss, the inputs are unchanged, and the served graph does not contain the
  spatial head (`pytorch/test_spatial.py` asserts this).
- Replication: a second match with a fresh master seed and the bots in the
  other seat order (`finalize-nwl23s.sh`), results in RESULTS.md.

## Why it plausibly works

The value head sees one outcome bit per position. The placement heads ask
the trunk, at every square, where the opponent's reply and the mover's own
next move will land and whether that player goes on to win. To answer, the
square tokens must encode live hooks, lanes, tile availability and how much
each spot matters, which is exactly the board knowledge a defensive value
judgement needs and which the outcome bit alone teaches slowly. The gain is
the same mechanism as KataGo's ownership head. The unweighted trunk gradient
of each spatial head grew from ~2% of the WDL head's at step 500 to ~15% by
step 5,500 as the trunk started to represent what they ask for.
